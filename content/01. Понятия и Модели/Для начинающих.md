# Для начинающих: как начать работать с ИИ

> [!abstract]
> Начни не с терминов и инструментов, а с одной реальной задачи. Дай модели понятный контекст, проверь результат и только потом усложняй процесс.

## 1. Понять главное

LLM генерирует ответ на основе обучения и переданного [[Context Window|контекста]]. Она умеет объяснять, писать, преобразовывать информацию и предлагать решения, но не проверяет автоматически каждое своё утверждение.

Три правила на старте:

1. Уверенный ответ не обязательно верный — важные факты проверяй по источникам.
2. Модель видит только переданный ей контекст и возможности выбранного продукта.
3. Не отправляй пароли, ключи, персональные или рабочие данные без понимания настроек приватности.

Для базы достаточно сначала прочитать [[Token]], [[Context Window]] и [[Hallucination]].

## 2. Выбрать подходящий режим

| Задача | С чего начать |
| :--- | :--- |
| Объяснить тему, придумать варианты, отредактировать текст | Обычный чат |
| Найти свежие факты и источники | Чат с веб-поиском; проверяй даты и ссылки |
| Ответить по своим документам | Загрузка нужных файлов или [[RAG]] |
| Изменить много файлов, запустить команды или тесты | [[Agent|агент]] с ограниченными правами |
| Работать без передачи данных облачному API | [[_Local AI Index|Локальный ИИ]], если позволяет железо |

Не выбирай агента только потому, что он «мощнее». Если задачу можно безопасно решить одним ответом, обычный чат проще и предсказуемее.

## 3. Поставить первую задачу

Хороший запрос содержит четыре части:

```text
Цель: что должно получиться.
Контекст: данные, аудитория и исходные материалы.
Ограничения: что нельзя менять, какой нужен объём и стиль.
Результат: формат ответа и критерий готовности.
```

Пример:

```text
Цель: превратить эту заметку в краткую инструкцию для новичка.
Контекст: читатель впервые пользуется ИИ; исходный текст ниже.
Ограничения: не добавляй неподтверждённые факты, уложись в 500 слов.
Результат: Markdown с короткими разделами и чеклистом в конце.
```

Не обязательно писать идеальный промпт сразу. Получи черновик, укажи конкретную проблему и сделай ещё одну итерацию.

## 4. Проверить результат

Перед использованием ответа спроси себя:

- Выполнена ли исходная цель?
- Не придуманы ли факты, ссылки, цитаты или команды?
- Можно ли проверить важные утверждения по первичному источнику?
- Сохранились ли ограничения и нужный формат?
- Если агент менял файлы — виден ли diff и запускались ли подходящие проверки?
- Если действие внешнее или необратимое — подтвердил ли его человек?

[[Structured Output|Правильный формат]] и красивое объяснение не доказывают правильность содержания.

## 5. Перейти к агентам, когда появится задача

Агент полезен, когда работа состоит из нескольких шагов и требует файлов, команд или внешних инструментов. Начинай с небольшой папки и минимальных разрешений.

Для работы с проектами можно использовать Claude Code или другой совместимый coding agent:

- [[Быстрый старт Claude Code]] — установка и первая безопасная сессия.
- [[_Claude Code Index|Раздел Claude Code]] — более подробные материалы.
- [[Инструкция по эксплуатации]] — общий рабочий цикл, не привязанный к одному продукту.

Перед запуском сформулируй критерий готовности и явно укажи, что разрешено менять. Удаление, публикацию, оплату и отправку сообщений лучше оставлять за подтверждением человека.

> [!tip] Самый полезный первый эксперимент
> Возьми небольшой текст, попроси сделать две версии результата с разными ограничениями, сравни их и объясни модели, что именно нужно исправить. Так быстрее всего становится понятно, что ИИ — не оракул, а управляемый инструмент.
