# 📐 Архитектура Навыка: Единый стандарт

> [!abstract] Назначение
> Данный стандарт определяет структуру описания навыков (AI Skills). Он превращает абстрактное "умение" в готовый программный модуль, который можно мгновенно интегрировать в любую среду (Cursor, Claude Code, Terminal).

---

## 🏗️ Структура описания (Шаблон)

Каждый новый навык в папке `Examples` должен быть оформлен по следующим пунктам:

### 1. Паспорт Навыка
* **Название:** Понятное имя (напр. "Research-Verifier").
* **Роль:** Какую "шляпу" надевает ИИ (напр. "Специалист по фактчекингу").
* **Уровень:** Атомарный / Композитный / Когнитивный.

### 2. Стек инструментов (Stack)
Список необходимых MCP-серверов или локальных ресурсов:
* `tool_name` — для чего используется в рамках этого навыка.

### 3. Логика и Паттерны (Reasoning)
Описание когнитивного процесса. Ссылки на методы мышления из базы:
* Связь с [[Chain of Thought (CoT)]] или другими техниками.
* Пошаговый алгоритм: что ИИ делает в первую очередь, как проверяет результат.

### 4. Конфигурационный блок (Implementation)

Это универсальная инструкция для "прошивки" агента.

> [!tip] Как использовать этот блок
> - **В IDE (Cursor):** Добавь текст в файл `.cursorrules` в корне проекта.
> - **В CLI (Claude Code):** Добавь текст в раздел `Guidelines` файла `CLAUDE.md`.
> - **В System Prompt:** Используй как префикс к своим запросам.

#### 📋 Инструкция для копирования:
```markdown
### [Название Навыка]
- **Goal:** [Краткая цель]
- **Protocol:** [Основные шаги алгоритма]
- **Constraints:** [Что запрещено делать]
- **Tools:** [Список используемых MCP-серверов]
```

### 5. Контроль качества (Definition of Done)
Критерии успешного выполнения:
* Пример: "Данные проверены в 3 независимых источниках".
* Пример: "Файл создан и соответствует структуре проекта".

---

## 🛠️ Пример быстрого применения
Если навык описан по этому стандарту, ты просто открываешь файл, копируешь содержимое раздела **4 (Implementation)** и вставляешь в конфиг своего проекта. Агент мгновенно получает новую компетенцию.
