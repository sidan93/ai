# Архитектура навыка

> [!abstract] Назначение
> Этот шаблон помогает описать переносимую операционную процедуру. Файл навыка, project rules и system prompt могут использовать разные форматы, поэтому адаптируй упаковку под конкретную платформу.

## Паспорт

- **Название:** короткое и различимое.
- **Цель:** наблюдаемый результат.
- **Использовать когда:** явные триггеры.
- **Не использовать когда:** границы и противопоказания.
- **Вход:** обязательные данные.
- **Выход:** формат результата.
- **Зависимости:** tools, MCP-серверы, скрипты, шаблоны и справочники.

## Процедура

Описывай шаги действиями, а не ролями:

1. Найти необходимый контекст.
2. Проверить ограничения и права.
3. Выполнить преобразование или вызвать tool.
4. Проверить результат независимым способом.
5. Исправить обнаруженные ошибки.
6. Вернуть результат и существенные оговорки.

## Безопасность

Для каждого изменяющего tool укажи:

- допустимые цели;
- запрещённые операции;
- необходимость подтверждения;
- способ предварительного просмотра;
- возможность отката;
- обращение с секретами и персональными данными.

## Definition of Done

Критерии должны проверять результат, например:

- все обязательные поля присутствуют;
- ссылки разрешаются;
- тесты проходят;
- факты имеют источники;
- изменены только файлы в области задачи;
- пользователь видит, что именно изменилось.

«Агент считает работу законченной» критерием не является.

## Минимальный шаблон

```markdown
# Название

## Когда использовать
...

## Когда не использовать
...

## Вход и зависимости
...

## Процедура
1. ...

## Безопасность
...

## Проверка результата
...
```

## Размещение

- Правила проекта хранятся в принятом файле инструкций проекта.
- Переносимый skill оформляется по спецификации конкретного агента.
- Tools передаются через API или MCP и не заменяются текстовым описанием.
- Большие справочники лучше держать отдельными ресурсами и загружать по необходимости.
