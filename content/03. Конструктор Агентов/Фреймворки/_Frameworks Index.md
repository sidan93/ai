# Фреймворки для ИИ-приложений

> [!abstract] Главное
> Сначала выбери архитектуру и критерии качества, затем библиотеку. Фреймворк уменьшает объём связующего кода, но не делает систему автоматически надёжной.

## Карта

| Фреймворк | Основной фокус | Когда смотреть |
| :--- | :--- | :--- |
| [[LangChain]] / LangGraph | Tool-calling агенты, графы состояния, интеграции | Нужна гибкая оркестрация и широкая экосистема |
| [[LlamaIndex]] | Ingestion, retrieval и data-centric приложения | Основная сложность находится в данных и RAG |
| [[Haystack]] | Явные pipelines для поиска и генерации | Нужны модульные, тестируемые data pipelines |
| [[CrewAI]] | Ролевые команды и flows | Ролевая декомпозиция действительно соответствует процессу |
| [[AutoGen]] | AgentChat и event-driven multi-agent runtime | Исследуется коммуникация агентов или нужен Core runtime |

Также существуют PydanticAI, Semantic Kernel и другие варианты. Не добавляй библиотеку только ради моды: для простого агента может хватить SDK провайдера и собственного цикла.

## Критерии выбора

1. Поддержка нужных моделей и tools.
2. Явное состояние и возобновление после сбоя.
3. Structured output и валидация.
4. Трассировка и evals.
5. Async, streaming и deployment.
6. Политика обновлений и breaking changes.
7. Возможность ограничивать инструменты и подтверждать действия.
8. Стоимость замены фреймворка, если проект вырастет.

## Минимальный эксперимент

Перед выбором реализуй один и тот же сценарий в двух вариантах:

- один запрос с tool calling;
- один цикл с ошибкой инструмента;
- сохранение и восстановление состояния;
- трассировка;
- тест на prompt injection;
- измерение числа строк собственного кода и сложности отладки.
