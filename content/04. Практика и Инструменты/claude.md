# Claude: чат, Cowork и работа с кодом

> [!abstract] Суть
> Claude — имя семейства моделей и продуктов Anthropic. Для начала важнее выбрать способ работы: обсудить вопрос, поручить задачу с готовым результатом или изменить программный проект. Приложение, модель и место выполнения задачи — разные вещи.

Два слова, которые встретятся ниже: **репозиторий** — папка проекта с историей изменений в Git; **diff** — список добавленных, удалённых и изменённых строк.

Карта актуальна на **31 октября 2026 года**. Доступность функций зависит от тарифа, устройства, настроек организации и постепенного обновления интерфейса. Названия кнопок могут отличаться от описания.

## Что открыть под свою задачу

| Хочу | С чего начать | Что проверить в результате |
| :--- | :--- | :--- |
| Разобраться в вопросе, обсудить идею, улучшить текст | Разговор с Claude на сайте или в приложении | Верность объяснения, фактов и формулировок |
| Поручить работу с документами и получить готовый материал | Cowork, если доступен в аккаунте | Сам файл или другой результат, использованные источники и выполненные действия |
| Разобрать репозиторий, исправить код, запустить проверки | Claude Code | Изменённые файлы, diff, команды и результаты тестов |

**Приложение — это место, где ты открываешь работу.** Установить его не означает автоматически дать доступ ко всем файлам компьютера. **Модель** отвечает на запросы и выбирает действия; **среда** предоставляет файлы и инструменты; **права** ограничивают их использование. Перед сложной задачей полезнее проверить эти четыре вещи, чем искать одну «правильную» кнопку Claude.

## Разговор: самый простой первый шаг

Можно начать без установки: открыть [claude.ai](https://claude.ai/), войти и задать вопрос. Например: «Объясни этот текст для человека без технического опыта. Отдельно перечисли непонятные места». Дай нужный контекст и желаемую форму ответа, затем уточняй результат. Доступная модель выбирается в интерфейсе; её название не определяет само по себе доступ к твоему проекту. [Начало работы с Claude](https://support.claude.com/en/articles/8114491-get-started-with-claude).

Чат полезен для обсуждения решения до изменений. Если ты вставил функцию и получил исправленный вариант, файл в репозитории ещё не обязательно изменён. С другой стороны, разговор не ограничен простым текстом: доступные инструменты могут добавлять поиск и работу с материалами. Поэтому различай **совет**, **созданный артефакт** и **выполненное действие** по фактическому результату, а не по виду окна.

Для первого знакомства достаточно одного небольшого материала без секретов. Не нужно заранее подключать все приложения или переносить весь архив: добавляй источник, когда понятно, зачем он нужен задаче.

## Cowork: поручить результат из нескольких шагов

Cowork предназначен для работы за пределами разработки: например, собрать сведения и подготовить документ. Вместо серии отдельных вопросов можно описать результат, исходные материалы и ограничения. Задача выполняется **в облаке**, а доступ к ней предусмотрен через web, mobile и desktop с условиями для разных аккаунтов. Она может продолжаться при закрытом ноутбуке. [Официальное руководство Cowork](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork).

Chat и Cowork постепенно объединяются в одном интерфейсе. У части пользователей есть переключатель, у других уже единое поле ввода. Отсутствие отдельной вкладки не доказывает отсутствие возможностей. Для доступа к локальным файлам или браузеру компьютера нужно открытое и подключённое desktop-приложение на поддерживаемой системе. Сам облачный сеанс может продолжаться без ноутбука, но зависимые от него действия требуют доступного компьютера.

Хорошая постановка: «Подготовь черновик обзора по этим трём материалам. Сохрани ссылки, отметь противоречия, ничего не отправляй другим людям». Принимай готовый документ по содержанию; слово «готово» не заменяет чтение результата.

## Claude Code: работать внутри проекта

Claude Code читает код, редактирует файлы и запускает команды в доступной среде. С ним можно начать с исследования проекта, затем перейти к изменению и проверке. Это рабочий инструмент для репозитория; знакомый диалог служит способом поставить задачу. [Обзор Claude Code](https://code.claude.com/docs/en/overview).

| Интерфейс | Для чего удобен | Где искать результат |
| :--- | :--- | :--- |
| **CLI** — терминал | Работа рядом с командами проекта | Файлы рабочей папки, diff и вывод команд |
| **Desktop** | Визуальный просмотр сессии, файлов и изменений | Выбранная среда и её рабочая копия |
| **Web** — браузер | Облачная задача без локальной установки CLI | Изменения облачной сессии, затем предусмотренный способ переноса в проект |

CLI обычно начинают в папке проекта; первый сеанс включает вход и знакомство с кодом. Установку и команды здесь не повторяем: для них есть [[Быстрый старт Claude Code]]. [Официальный quickstart](https://code.claude.com/docs/en/quickstart).

Для работы с кодом в приложении **Claude Desktop открой раздел Code** — это интерфейс Claude Code. Обычный разговор и Cowork в том же приложении не означают, что ты уже открыл Code. Перед работой в Code выбирают среду и проект. Варианты включают Local, Cloud и SSH; следовательно, «открыл приложение на ноутбуке» ещё не отвечает на вопрос, где выполняются команды. Просмотр diff помогает увидеть фактические изменения. [Desktop](https://code.claude.com/docs/en/desktop).

## Локально, в облаке и при закрытом ноутбуке

**Локальная сессия** использует окружение компьютера. Это не означает локальную модель или полностью офлайн-работу. Если управляешь такой сессией с телефона через **Remote Control**, исполнение остаётся на исходной машине: ей нужно работать, а процесс Claude Code должен быть запущен. Remote Control не переносит задачу в облако. [Remote Control](https://code.claude.com/docs/en/remote-control).

**Облачная сессия Claude Code** выполняется в удалённой среде и продолжает работу после закрытия ноутбука. Ей нужны доступный код, зависимости и разрешённая сеть. GitHub — один из путей передачи репозитория; документация также описывает отправку локального репозитория из CLI без GitHub. Нельзя считать локальные незагруженные файлы автоматически доступными в облаке. [Claude Code in the cloud](https://code.claude.com/docs/en/claude-code-on-the-web).

До запуска уточни: какая рабочая копия выбрана, какие файлы попадут в среду и как ты заберёшь результат. Успешная облачная проверка не доказывает, что изменение уже находится в твоей основной ветке или опубликовано.

## Пример: от обсуждения к проверенному изменению

> [!example] Иллюстрация
> Вымышленный проект; Claude Code и команды для этого примера не запускались.

В приложении список задач неверно показывает пустой результат поиска.

1. **Обсудить.** В чате сформулировать ожидаемое поведение: при отсутствии совпадений показать понятное сообщение, сохранить остальные функции.
2. **Исследовать.** Открыть репозиторий в Claude Code: «Найди реализацию поиска и связанные тесты. Пока не меняй файлы. Объясни причину ошибки».
3. **Ограничить изменение.** Попросить исправить найденный сценарий, сохранить существующие пользовательские правки и не публиковать результат.
4. **Проверить действия.** Увидеть, какие файлы изменены и какую команду проверки предлагает агент. При запросе разрешения сопоставить действие с задачей.
5. **Принять результат.** Просмотреть diff, вывод тестов и вручную проверить пустой и непустой поиск. Если тест не запускался из-за окружения, это остаётся непроверенной частью.

Обсуждение могло пройти в одном продукте, исполнение — в другом. Передавай согласованные требования явно: не рассчитывай, что новый сеанс сам знает все решения прежнего разговора.

## Права и частая путаница

В Claude Code permission modes и правила определяют, какие действия требуют подтверждения. В одних режимах запрос видит пользователь, в других часть действий рассматривается автоматически. Отсутствие вопроса не доказывает отсутствие операции. [Permissions](https://code.claude.com/docs/en/permissions).

Смотри на конкретное действие: чтение файла, изменение, команда, сетевой запрос или публикация. Разрешение поправить код не стоит формулировать как неограниченное право распоряжаться репозиторием. Постоянные правила проекта размещают в `CLAUDE.md`; они помогают направить работу, но не заменяют контроль доступа.

Для начала запомни три проверки: **что дано на входе, где выполняется работа, чем подтверждён результат**. Готовый код в ответе, изменённый файл, успешный тест и опубликованное приложение — четыре разных результата.
