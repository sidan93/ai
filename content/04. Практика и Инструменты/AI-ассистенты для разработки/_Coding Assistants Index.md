# AI-ассистенты для разработки

> [!abstract] Суть
> Coding-agent читает проект, меняет файлы и запускает команды в пределах доступной ему среды. Выбирай не «самую умную модель», а весь рабочий контур: интерфейс, права, инструкции, review, тесты и восстановление.

## Начать

- [[Рабочий цикл с coding-агентом]] — общий процесс, одинаково полезный для разных продуктов.
- [[Быстрый старт Codex]] — CLI, вход, `AGENTS.md`, permissions и review.
- [[Быстрый старт Claude Code]] — CLI, вход, `CLAUDE.md` и permissions.
- [[Engineering Loop]] — один из более строгих процессов для Claude Code, а не обязательный стандарт.

## Как выбирать инструмент

| Критерий | Что проверить на своём проекте |
| :--- | :--- |
| Среда | CLI, IDE, desktop, cloud; где реально исполняются команды |
| Контекст | Какие файлы и инструкции загружаются автоматически |
| Контроль | Sandbox, allow/deny rules, approvals и сетевой доступ |
| Работа | Diff, review, checkpoints, resume и параллельные задачи |
| Расширение | Skills, MCP, hooks/plugins и CI |
| Цена | Подписка, API или квоты; стоимость успешной задачи |

## Минимальный безопасный старт

1. Открой небольшой знакомый репозиторий с чистым `git status`.
2. Попроси только объяснить структуру — без изменений.
3. Дай одну локальную задачу с проверяемым результатом.
4. Просмотри diff и команды, затем запусти тесты самостоятельно.
5. Добавляй постоянное правило только после повторившейся ошибки.

## Не смешивать

- coding-agent — готовый рабочий продукт;
- [[Harness]] — среда и механики вокруг модели;
- [[OpenAI Agents SDK]] или иной framework — библиотека для создания собственного агента;
- IDE autocomplete — подсказка кода без полноценного agent loop.
