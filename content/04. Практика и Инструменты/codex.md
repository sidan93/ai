# Codex: что открыть и как начать работу

> [!abstract] Суть
> **Codex** — агент OpenAI для разработки и технических задач. Он может исследовать проект, менять файлы и запускать команды в доступной среде. Для начала нужно выбрать не только удобное окно, но и компьютер, на котором будет выполняться работа.

Эта страница — карта продукта для первого знакомства. Установка и команды вынесены в [[Быстрый старт Codex]]. Возможности сверены **31 октября 2026 года**; доступность зависит от аккаунта, workspace, версии клиента и этапа внедрения функций.

---

## Chat, Work и Codex: три разных намерения

В текущем ChatGPT есть **Chat** для быстрых вопросов и обсуждения и **Work** для многошаговой работы с готовым результатом. Например, объяснить таблицу можно в Chat, а исследовать материалы и подготовить документ — в Work. Codex ориентирован на разработку: репозиторий (папка проекта под управлением Git), файлы, команды, проверки.

На desktop сначала выбирают ChatGPT или отдельное представление Codex; внутри ChatGPT переключаются между Chat и Work. История Codex отделена от истории ChatGPT. На mobile тоже доступны Chat и Work, а coding-задачи можно вести через Codex Cloud или поддерживаемое подключение к компьютеру. [ChatGPT Work and Codex](https://help.openai.com/en/articles/20001275-chatgpt-work-and-codex).

Модель выбирается внутри агента: она обрабатывает запросы, а Codex предоставляет рабочие инструменты и интерфейсы. Смена модели сама по себе не переносит файлы и не выдаёт новые права.

Это выбор по характеру результата, а не граница «чат ничего не умеет, агент умеет всё». Для вопроса «почему эта функция ошибается?» достаточно обсуждения. Если нужно найти её в проекте, исправить и проверить — открывай среду Codex с доступом к этому проекту.

## CLI, редактор и приложение: где удобнее работать

**CLI** означает command-line interface — интерфейс командной строки. Codex CLI запускается в терминале командой `codex` из папки проекта. Он читает файлы, вносит изменения и вызывает установленные инструменты. Это самостоятельный coding-agent; не путай его с `openai`, CLI-клиентом OpenAI API. [Codex CLI](https://learn.chatgpt.com/docs/codex/cli).

| Вариант | Когда выбирать | Что важно перед стартом |
| :--- | :--- | :--- |
| Codex CLI | Уже работаешь в терминале и хочешь видеть команды рядом с диалогом | Правильная рабочая папка и доступные инструменты |
| IDE integration | Читаешь или исправляешь код в редакторе | Открытый проект и явно выбранный контекст |
| Desktop app, представление Codex | Удобнее вести задачи в графическом приложении | Выбранные проект, папка и место исполнения |
| Codex Cloud | Нужна задача в подготовленной облачной среде | Подключённый репозиторий, зависимости и права среды |

В IDE можно передавать открытые файлы и выделенные фрагменты, а затем просматривать изменения рядом с исходником. Способ включения зависит от редактора: расширение для VS Code и совместимых редакторов отличается от интеграций Xcode и JetBrains. [Codex IDE extension](https://learn.chatgpt.com/docs/codex/ide).

Desktop даёт общее рабочее пространство для проектов и результатов. Выбери Codex, открой нужную папку или проект и опиши задачу. Само наличие приложения не означает, что каждый его сеанс выполняется локально. [Desktop app](https://learn.chatgpt.com/docs/app).

## Локально, в облаке или через Remote

**Локальная работа** использует выбранную папку и инструменты компьютера. Если тестам нужен установленный Python или запущенная база данных, их наличие имеет значение. При этом «локально» описывает место исполнения команд: это не обещание, что модель работает без сети или данные диалога не обрабатываются облачными сервисами.

**Codex Cloud** исполняет задачу на компьютере под управлением OpenAI. Среду с репозиториями, инструментами и настройками доступа создают и публикуют через desktop или web; готовую среду можно выбрать для мобильной задачи. Каждая задача получает отдельное рабочее пространство. Работа может продолжаться, пока твой компьютер спит. Чтобы продолжить незавершённые изменения, вернись в исходную задачу: новая не подхватит автоматически её незакоммиченные файлы. [Using Codex Cloud](https://help.openai.com/en/articles/20001545-using-codex-cloud).

**Remote** — подключение к работе на другом устройстве. Телефон передаёт инструкции и показывает результат, а файлы и команды остаются на подключённом host. Если этот компьютер уснул, потерял сеть или закрыл приложение, доступ прекращается до восстановления. В приложении для iOS раздел может называться Codex; если интерфейс ещё показывает Remote, используй его. Это отдельный способ доступа, а не перенос задачи в Codex Cloud. [Remote connections](https://learn.chatgpt.com/docs/remote-connections).

Практическая проверка перед поручением: **какая папка открыта, где выполняется команда и куда попадёт изменённый файл?** Одинаковый диалог на двух устройствах ещё не отвечает на эти вопросы.

## Первая задача: от разговора к проверяемому изменению

Для первого знакомства возьми небольшой знакомый репозиторий. Проверь текущее состояние Git, чтобы отличать собственные незавершённые изменения от новых. Для CLI после установки и входа достаточно открыть папку и запустить `codex`; подробности — в [[Быстрый старт Codex]].

Ниже **вымышленный пример**, не результат выполненного запуска. В Python-проекте функция `parse_port` должна принимать номера портов от 1 до 65535, но ошибочно принимает ноль.

**1. Сначала разобраться.**

> Прочитай инструкции проекта и найди parse_port. Объясни текущую проверку и существующие тесты. Пока не меняй файлы.

Codex должен показать, где находится логика и на чём основан вывод. Если функция отсутствует или проект устроен иначе, это повод уточнить задачу, а не создавать похожий файл наугад.

**2. Затем поручить изменение.**

> Исправь принятие нулевого порта. Сохрани остальные правила разбора. Добавь проверку границ 0, 1, 65535 и 65536, запусти относящиеся к функции тесты. Не устанавливай зависимости и не делай commit или push.

В предполагаемом проекте результатом будут изменения `src/config.py` и `tests/test_config.py`. Команда проверки может выглядеть как `python -m pytest tests/test_config.py`, но выбирать её нужно по реальным инструкциям проекта. Названия здесь иллюстрируют ожидаемый результат, а не универсальную структуру Python-приложения.

**3. Принять работу.**

Попроси показать diff — список изменённых строк, — выполненные команды, их результат и оставшиеся ограничения. Если pytest отсутствует, честный итог — «изменение подготовлено, тесты не запущены», а не «всё работает». Затем проверь сами изменённые строки: тест на ноль полезен, но случайно сломанный разбор строк тоже важен. Полный порядок — [[Рабочий цикл с coding-агентом]].

## Права и подтверждения: что именно ты разрешаешь

У Codex есть два разных механизма. **Sandbox и permissions** ограничивают технический доступ к файлам и сети. **Approval policy** определяет, когда действие требует дополнительного согласования. В зависимости от настройки запрос может поступить человеку или на автоматическую проверку. [Agent approvals & security](https://learn.chatgpt.com/docs/agent-approvals-security).

Начинай с доступа, достаточного для задачи: чтение для знакомства, запись в выбранный проект для исправления. Не расширяй права на весь компьютер только ради исчезновения одного запроса. Для первого запуска проверь доступные настройки прав в интерфейсе. [Permissions](https://learn.chatgpt.com/docs/permissions).

Разрешение изменить файл и решение опубликовать результат — разные части задания. Формулируй границы явно: «исправь локально», «подготовь PR» или «выполни согласованную публикацию». Отчёт агента проверяй по артефактам: diff подтверждает изменение, вывод команды — запуск проверки, ссылка на PR — создание PR. Одно не доказывает другое.
