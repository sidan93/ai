# Локальный запуск моделей

> [!abstract] Суть
> «Локально» означает, что инференс выполняется на твоём устройстве. Это может дать офлайн-режим и больше контроля над данными, но только если интерфейс, инструменты, embeddings, телеметрия и fallback тоже не обращаются к облаку.

## Маршрут без лишней путаницы

1. [[Железо для локальных моделей]] — оцени память и скорость.
2. [[Форматы и квантование]] — выбери совместимый файл и квант.
3. [[Ollama]] или [[LM Studio]] — выбери runtime.
4. Выбери интерфейс по таблице ниже; отдельный UI нужен не каждому сценарию.
5. [[Top_LLM_Index_2026-10|Выбор моделей]] — собери короткий список и проверь его на своих задачах.

## Runtime и интерфейс: что выбрать

Runtime загружает и исполняет модель, а интерфейс отправляет запросы и хранит пользовательское состояние. Некоторые приложения совмещают обе роли.

| Инструмент | Роль | Когда подходит |
| :--- | :--- | :--- |
| [[Ollama]] | Runtime, CLI и API | Нужен backend для скрипта, плагина или отдельного UI |
| [[LM Studio]] | Desktop-приложение и локальный сервер | Нужны каталог моделей, настройка загрузки, ручной чат и API |
| [Open WebUI](https://docs.openwebui.com/) | Интерфейс к Ollama и совместимым API | Нужен web UI поверх выбранного runtime, в том числе для работы с документами |
| [Jan](https://docs.jan.ai/) | Desktop-приложение с локальным API-сервером | Нужен локальный чат и сервер в одном приложении |
| [llama.cpp](https://github.com/ggml-org/llama.cpp) | Runtime и server | Нужен более прямой контроль над запуском модели |

Для автоматизации сначала выбирай runtime/API, затем UI. Для ручного сравнения моделей удобен desktop-интерфейс. Если пользователей несколько, отдельно проверь аутентификацию и разграничение доступа выбранного web UI.

Например, скрипту, который отправляет запрос локальной модели, отдельный чат-интерфейс не нужен. А для Obsidian сначала определи задачу: обычный поиск, embeddings или [[RAG (Retrieval-Augmented Generation)|RAG]], — и лишь затем добавляй систему работы с документами.

## Локальное и облачное — не одно и то же

Современный инструмент может поддерживать оба режима. Например, Ollama предлагает локальные и облачные модели, а LM Studio — локальный сервер и совместимые API. Всегда проверяй, **где исполняется конкретная модель**, какой endpoint использует клиент и нет ли облачного fallback.

## Что проверить перед использованием

- Архитектура модели, формат весов и нужные tools/function calling поддерживаются runtime и клиентом.
- Модель действительно загружена и исполняется локально; endpoint ведёт на нужный локальный сервер, а не в облако.
- Web search, MCP и другие tools не отправляют данные наружу без необходимости; embeddings тоже локальные, если это требование.
- История, телеметрия, синхронизация и резервные копии настроены осознанно.
- При доступе не только с `localhost` проверены аутентификация, firewall и TLS.
- Лицензия и порядок обновления проекта подходят сценарию использования.

> [!warning] Загрузка PDF — ещё не качественный RAG
> Проверь разбиение текста, embeddings, retrieval, ссылки на источники и поведение системы, когда ответа в документах нет.
