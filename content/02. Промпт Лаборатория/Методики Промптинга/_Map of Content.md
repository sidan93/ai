# Prompt Engineering: карта раздела

Промпт-инжиниринг — это проектирование входа, инструкций и критериев результата для модели. Качество зависит не от одной «секретной формулы», а от сочетания понятной задачи, подходящего контекста, доступных инструментов и проверки на реальных примерах.

## С чего начинать

1. [[Outcome-first Prompting]] — опиши результат, критерии готовности и ограничения.
2. [[Delimiters]] — отдели инструкции, данные и примеры.
3. [[Zero-shot vs Few-shot Prompting]] — сначала попробуй без примеров, затем добавь качественные демонстрации, если они нужны.
4. Укажи формат ответа; для API предпочитай [[Structured Output]], когда он доступен.
5. Улучшай промпт через [[Тестирование промптов]], а не по одному удачному ответу.

## Основные методы

### Управление задачей и контекстом

- [[Outcome-first Prompting]] — цель, критерии успеха, границы и условия остановки.
- [[Delimiters]] — явная структура промпта и недоверенных данных.
- [[Persona Prompting]] — рабочая перспектива и стиль без притворной квалификации.
- [[Negative Prompting]] — точечные запреты вместе с положительными требованиями.
- [[Atomic Notes]] — подготовка самостоятельных единиц знания.

### Примеры и формат

- [[Zero-shot vs Few-shot Prompting]] — выбор между инструкцией и демонстрациями.
- [[Few-Shot Chain of Thought]] — специализированные примеры решения, когда важен метод, а не только формат.

### Декомпозиция и рассуждение

- [[Chain of Thought (CoT)]] — проверяемые промежуточные результаты вместо запроса скрытого рассуждения.
- [[Least-to-Most Prompting]] — последовательное решение зависимых подзадач.
- [[Step-Back Prompting]] — проверка применимых принципов перед частным решением.
- [[Prompt Chaining]] — последовательность проверяемых вызовов и граница между prompting и workflow.

### Сжатие и проверка

- [[Chain of Density (CoD)]] — экспериментальная итеративная суммаризация.
- [[Chain of Verification (CoVe)]] — самопроверка черновика отдельными вопросами.
- [[Iterative Prompting]] — управляемое улучшение инструкции.
- [[Тестирование промптов]] — набор кейсов, метрики и регрессионная проверка.

## Быстрый выбор

| Ситуация | Первый выбор |
|---|---|
| Нечёткая задача | [[Outcome-first Prompting]] |
| Нестабильный формат | [[Zero-shot vs Few-shot Prompting]] или [[Structured Output]] |
| Большой недоверенный документ | [[Delimiters]] и правила из [[Indirect Prompt Injection]] |
| Несколько зависимых этапов | [[Least-to-Most Prompting]] |
| Нужны отдельные контракты и проверки между этапами | [[Prompt Chaining]] |
| Важные факты | внешние источники + [[Chain of Verification (CoVe)]] |
| Потеря деталей при сокращении | [[Chain of Density (CoD)]] с проверкой сохранности |
| Улучшение рабочего шаблона | [[Тестирование промптов]] |

## Чего избегать

- Не начинай с роли, если можно прямо описать требуемый результат.
- Не проси «думать пошагово» по привычке; запрашивай проверяемые промежуточные артефакты только когда они полезны.
- Не считай уверенный тон доказательством.
- Не полагайся на разделители как на защиту от prompt injection.
- Не оценивай промпт по одному примеру и одной модели.
- Не заставляй модель генерировать `[[ссылки]]`, если у неё нет списка существующих заметок.
