# Least-to-Most Prompting

Least-to-Most разбивает сложную задачу на более простые зависимые подзадачи и решает их по порядку, используя предыдущие результаты.

## Два этапа

1. **Декомпозиция:** определить минимальные подзадачи и зависимости.
2. **Последовательное решение:** выполнить их от базовых к составным, проверяя результат каждого этапа.

```text
Цель: {сложная задача}

Сначала составь список подзадач. Для каждой укажи входные данные,
ожидаемый результат и зависимости. Не выполняй лишние этапы.

Затем решай только готовые подзадачи. После каждого результата проверь,
достаточно ли доказательств для следующего шага. Не переноси догадку как факт.
```

## Когда полезно

- составной результат зависит от нескольких промежуточных артефактов;
- проблему легче проверить частями;
- нужно продолжать работу после сбоя отдельного этапа;
- задача требует последовательного применения найденных сведений.

## Риски

- Ошибка раннего этапа распространяется дальше.
- Неудачная декомпозиция создаёт лишнюю работу или теряет глобальные ограничения.
- Независимые задачи выгоднее выполнять параллельно, если система это поддерживает.
- Для простой задачи план может стоить дороже самого решения.

В агентной системе сохраняй результаты этапов и проверяй условия остановки, а не полагайся только на длинный единый ответ.
