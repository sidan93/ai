# Интерфейсы для локальных LLM

> [!info] Базовая схема
> Runtime загружает и исполняет модель. Интерфейс отправляет ему запросы. Некоторые приложения совмещают обе роли.

## Основные варианты

| Инструмент | Роль | Когда подходит |
| :--- | :--- | :--- |
| [[Ollama]] | Runtime и API | Нужен простой backend для CLI, плагина или отдельного UI |
| [Open WebUI](https://openwebui.com/) | Браузерный интерфейс | Нужны пользователи, история, документы и расширяемый web UI |
| [Jan](https://jan.ai/) | Desktop all-in-one | Нужен простой локальный чат и встроенный сервер |
| [[LM Studio]] | Desktop all-in-one | Нужны поиск моделей, тонкая настройка и сравнение |
| [llama.cpp](https://github.com/ggml-org/llama.cpp) | Низкоуровневый runtime | Нужны контроль, переносимость и минимальный слой абстракции |

## Как выбрать

- Для автоматизации и API обычно удобнее Ollama или llama.cpp server.
- Для ручного подбора модели — LM Studio.
- Для домашнего многопользовательского интерфейса — Open WebUI.
- Для быстрого desktop-старта — LM Studio или Jan.

## Что проверить

- поддерживаемые форматы и архитектуры;
- хранение истории и телеметрию;
- работу tools/function calling;
- embeddings и RAG;
- управление доступом, если сервер открыт в локальную сеть;
- обновления и резервное копирование конфигурации.

> [!warning] RAG «из коробки»
> Наличие загрузки PDF ещё не означает качественный RAG. Проверяй разбиение текста, embeddings, retrieval, цитирование и поведение при отсутствии ответа в источниках.
