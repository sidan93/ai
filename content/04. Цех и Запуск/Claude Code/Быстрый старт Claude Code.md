# ⚡ Быстрый старт Claude Code

> [!abstract] Краткий обзор
> Эта заметка дает минимальный путь "с нуля до первой полезной сессии" в Claude Code: установка, запуск в проекте, базовые команды и безопасный рабочий цикл.

🔗 **Официальная документация:** [Claude Code Docs](https://docs.anthropic.com/en/docs/claude-code)

---

## 🏛️ Ключевые идеи
- **Запускай из корня проекта:** так агент сразу видит релевантный контекст и структуру кода.
- **Начинай с узких задач:** небольшие и проверяемые шаги дают предсказуемый результат.
- **Фиксируй результат итерациями:** после каждого изменения проверяй diff, тесты и только потом двигайся дальше.

---

## 💡 Где использовать (Use Cases)
- **Быстрые правки:** правки в 1-3 файлах, где нужно ускорить рутину.
- **Наведение порядка:** переименование, чистка дублирующегося кода, стандартизация стиля.
- **Техническая разведка:** быстро понять незнакомый участок репозитория перед изменениями.

---

## 🛠️ Технический разбор
### 1) Установка
```bash
# через npm (глобально)
npm install -g @anthropic-ai/claude-code
```

### 2) Подготовка окружения
```bash
# добавь ключ в shell-профиль
export ANTHROPIC_API_KEY="your_api_key_here"
```

### 3) Первый запуск
```bash
cd /path/to/your/project
claude
```

### 4) Базовый рабочий цикл
1. Сформулируй задачу в 1-2 предложениях с конкретным результатом.
2. Попроси агента сначала найти контекст, затем предложить правку.
3. После правки проверь `git diff`.
4. Прогони локальные проверки (`npm test`, `pytest`, `ruff`, `eslint` — по стеку проекта).
5. Зафиксируй изменения только после верификации.

### 5) Полезные практики
- Держи рядом файл с правилами проекта (`CLAUDE.md` или `.cursorrules`), чтобы агент не "угадывал" стандарты.
- Для крупных задач дроби работу на короткие этапы и явно подтверждай каждый шаг.
- Не начинай с автогенерации больших модулей без ограничений по стилю и архитектуре.

---

## ⚠️ Частые ошибки на старте
- **Слишком общий запрос:** "сделай все красиво" почти всегда приводит к хаотичным изменениям.
- **Пропуск проверки:** отсутствие тестов и ревью diff увеличивает риск регрессий.
- **Нет проектных правил:** без локальных инструкций качество решений плавает от сессии к сессии.
