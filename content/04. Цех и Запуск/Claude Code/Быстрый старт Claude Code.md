# ⚡ Быстрый старт Claude Code

> [!abstract] Краткий обзор
> Минимальный путь от установки до продуктивной работы в Claude Code: установка, первый запуск, базовый рабочий цикл и ключевые команды.

🔗 **Официальная документация:** [Claude Code Docs](https://docs.anthropic.com/en/docs/claude-code)

---

## 🏛️ Ключевые идеи

- **Запускай из корня проекта:** агент читает `CLAUDE.md` и видит структуру кода сразу.
- **Начинай с узких задач:** небольшие проверяемые шаги → предсказуемый результат.
- **Итеративный цикл:** после каждого изменения проверяй diff, тесты, и только потом двигайся дальше.
- **Контекст — ресурс:** длинные сессии дорожают. Используй `/compact` для сжатия истории.

---

## 🛠️ Установка

```bash
# Вариант 1: npm (глобально)
npm install -g @anthropic-ai/claude-code

# Вариант 2: Homebrew (macOS)
brew install claude-code

# Вариант 3: прямая установка (Windows/Linux)
npm install -g @anthropic-ai/claude-code --registry https://registry.npmjs.org
```

### API-ключ

```bash
# добавь в shell-профиль (.zshrc / .bashrc)
export ANTHROPIC_API_KEY="your_api_key_here"
```

Проверка: `claude --version` должен показать актуальную версию.

## 🚀 Первый запуск

```bash
cd /path/to/your/project
claude
```

Claude Code прочитает `CLAUDE.md` из корня проекта (если есть) и начнёт сессию. Работает в любом проекте — не только кодовом; Obsidian-базы, документация, конфиги — всё годится.

---

## 🔄 Базовый рабочий цикл

1. **Сформулируй задачу** в 1-2 предложениях с конкретным измеримым результатом.
2. **Дай агенту найти контекст** — пусть сам прочитает нужные файлы перед правкой.
3. **Проверь `git diff`** после каждого изменения.
4. **Прогони проверки:** `npm test`, `pytest`, `ruff check`, `eslint` — что применимо к проекту.
5. **Коммить только после верификации.**

Для системного подхода — используй [[Engineering Loop]]: 9-фазный инженерный контур, заточенный под Claude Code.

## ⌨️ Ключевые команды

| Команда | Назначение |
| :--- | :--- |
| `/compact` | Сжать историю диалога — сохраняет контекст, освобождает место. Выполнять при приближении к лимиту. |
| `/clear` | Полный сброс сессии — начать с чистого листа. |
| `/config` | Настройки: тема, модель, лимиты. |
| `/doctor` | Диагностика: проверить установку и конфигурацию. |
| `/help` | Список всех доступных команд. |
| `--thinking-mode` | Включить extended thinking для сложных задач (флаг при запуске). |

## 📋 Структура CLAUDE.md

Файл `CLAUDE.md` в корне проекта — главный способ управлять поведением агента. Что стоит включить:

```markdown
# Project Name

## Context
- Краткое описание проекта (2-3 предложения)
- Назначение ключевых папок

## Conventions
- Стиль кода, нейминг, структура файлов
- Язык документации, формат заметок (для Obsidian-баз)
- Правила коммитов

## Commands
- Как запустить тесты, линтер, сборку
```

Пример для Obsidian-базы: [[CLAUDE.md|CLAUDE.md этого vault]].

## ⚠️ Частые ошибки на старте

- **Слишком общий запрос:** «сделай красиво» → хаотичные изменения. Формулируй конкретно.
- **Пропуск `/compact`:** сессия теряет контекст или резко дорожает на длинных дистанциях.
- **Нет `CLAUDE.md`:** без проектных правил качество решений плавает от сессии к сессии.
- **Слишком большие задачи за раз:** дроби на этапы и явно подтверждай каждый шаг.
- **Игнорирование `git diff`:** даже умный агент может задеть не то, что ты просил.
