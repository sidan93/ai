# Быстрый старт Claude Code

> [!abstract] Суть
> Claude Code — агентный CLI для работы с репозиториями и другими файловыми проектами. Он читает контекст, предлагает или выполняет изменения и запускает команды в пределах выданных прав.

## Установка

Сначала проверь [актуальную официальную инструкцию](https://docs.anthropic.com/en/docs/claude-code/getting-started). Поддерживаемые способы установки меняются.

Традиционный вариант через npm:

```bash
npm install -g @anthropic-ai/claude-code
claude doctor
```

Не используй sudo для глобальной npm-установки. Официальная документация также описывает native/local installer и миграцию между способами установки.

## Авторизация

При первом запуске выбери поддерживаемый вариант:

- аккаунт Claude с подходящим планом;
- Anthropic Console;
- корпоративная платформа, например Bedrock или Vertex AI.

API-ключ — не единственный способ входа. Не записывай ключи в проектные заметки и git.

## Первый запуск

```bash
cd /path/to/project
claude
```

Перед первой правкой попроси агента:

1. прочитать файл инструкций проекта;
2. показать найденные ограничения;
3. описать предполагаемые изменения;
4. выполнить минимальный проверяемый шаг;
5. показать diff и результаты тестов.

## Основной цикл

1. Дай конкретную задачу и критерий готовности.
2. Позволь агенту найти связанный контекст.
3. Проверь план, если изменение рискованное или широкое.
4. После правок просмотри diff.
5. Запусти подходящие тесты и линтеры.
6. Не считай сообщение агента доказательством успешной проверки.

## Полезные команды

Команды меняются между версиями, поэтому `/help` — источник истины для установленной версии.

| Команда | Назначение |
| :--- | :--- |
| `/help` | Доступные команды |
| `/doctor` | Диагностика установки |
| `/compact` | Сжатие текущего контекста |
| `/clear` | Очистка разговора |
| `/config` | Настройки клиента |

Не добавляй неизвестный CLI-флаг из старой статьи, пока его нет в `claude --help`.

## Файл инструкций

В `CLAUDE.md` полезно хранить только устойчивые правила:

- назначение проекта;
- структуру ключевых папок;
- команды проверки;
- стиль и ограничения;
- действия, требующие подтверждения.

Большие справочники лучше держать отдельно: длинная инструкция расходует контекст в каждой задаче.
